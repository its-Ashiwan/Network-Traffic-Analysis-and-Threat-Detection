# DNS Anomaly Analysis

## Objective

The objective of this phase was to detect and investigate abnormal DNS activity using Zeek logs and a custom Python detection script. The analysis focused on identifying excessive DNS requests and unusual query behaviour that may indicate reconnaissance activity, malware communication, or DNS-based anomalies.

## Investigation Methodology

The DNS investigation was performed using the following workflow:

1. Generate DNS traffic from the attacker machine.
2. Capture network traffic using tcpdump.
3. Monitor network activity using Zeek.
4. Analyse DNS requests through `dns.log`.
5. Validate observations using packet captures.
6. Execute a custom Python detection script.
7. Generate alerts based on suspicious DNS behaviour.

---

## Zeek DNS Log Analysis

The Zeek `dns.log` file was analysed to identify:

* Source IP generating DNS requests
* Queried domains
* DNS request frequency
* Repeated DNS lookups
* Potentially suspicious DNS activity

## Detection Logic

A custom Python-based DNS anomaly detector was developed to analyse DNS requests recorded in Zeek logs.

The detector:

* Counts DNS requests generated by each host
* Identifies hosts with unusually high DNS activity
* Generates alerts when DNS activity exceeds a predefined threshold
* Assists analysts in quickly identifying suspicious systems

---

## Findings

The investigation revealed abnormal DNS activity originating from a single source host.

Key observations included:

* Large volume of DNS requests
* Repeated DNS queries generated in a short period
* Increased DNS activity compared to normal traffic patterns
* Successful alert generation by the custom detection script

The Python detection script successfully identified abnormal DNS behaviour and generated an alert highlighting the suspicious source host.

## Analyst Assessment

From a SOC analyst perspective, the observed DNS behaviour was considered anomalous because a single system generated a significantly higher number of DNS requests than expected during the monitoring period.

Although the activity was performed in a controlled laboratory environment, similar behaviour in a production network could indicate:

* DNS tunneling attempts
* Malware communication
* Command-and-control traffic
* Automated reconnaissance activity
* Suspicious outbound communications

---

## Conclusion

The DNS anomaly detection phase successfully demonstrated the use of Zeek, Wireshark and Python-based detection techniques to identify unusual DNS behaviour.

By combining network traffic monitoring, Zeek log analysis, packet-level investigation and custom detection engineering, the project simulated a realistic SOC workflow for detecting DNS-based anomalies and suspicious network activity.
