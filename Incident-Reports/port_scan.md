# 1. Executive Summary

During the port scan detection phase, network traffic generated by Nmap was captured and analyzed using Zeek, tcpdump, Wireshark and a custom Python detection script.

The investigation identified a source host performing connection attempts against multiple ports on a target system. The observed activity was successfully captured through packet captures and Zeek logs, then validated through manual analysis and automated detection.

The behavior was classified as port scanning because a single host attempted to communicate with numerous destination ports within a short period of time. Such activity is commonly associated with reconnaissance and service discovery.

This phase demonstrates how SOC analysts can identify reconnaissance activity using network monitoring and detection techniques.

---

# 2. Scope of Investigation

This investigation was conducted to:

* Identify the source of scanning activity.
* Review network connections recorded by Zeek.
* Validate scanning behavior through packet captures.

* Assess the security significance of the observed activity.

# 7. Analyst Assessment

The activity was classified as port scanning because:

* Numerous ports were targeted within a short timeframe.
* Connection attempts originated from a single source host.
* SYN-based scanning behavior was observed.
* Automated detection generated a scan alert.
* Zeek and Wireshark findings were consistent.

Port scanning is commonly used by attackers to identify active services before exploitation attempts.

Although the activity was generated in a controlled lab environment, similar behavior in a production network should be investigated immediately.
