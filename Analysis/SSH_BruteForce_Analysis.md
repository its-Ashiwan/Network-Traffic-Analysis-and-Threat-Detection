# SSH Brute Force Attack Analysis

## 1. Objective

The objective of this investigation was to detect, analyze, and validate SSH brute force activity using Zeek network logs, packet captures, and custom detection scripts.

The analysis was conducted from a SOC analyst perspective where the attacker IP was initially considered unknown. The goal was to identify the suspicious host, determine the targeted service, validate the activity using network evidence, and generate actionable findings.

---

## 2. Lab Environment

| Role              | System        | Purpose                         |
| ----------------- | ------------- | ------------------------------- |
| Attacker          | Kali Linux    | Generated brute force traffic   |
| Target            | Ubuntu Server | Hosted SSH service              |
| Monitoring System | Ubuntu + Zeek | Traffic monitoring and analysis |

All systems were connected through a Host-Only network to ensure a controlled and isolated testing environment.

---

## 3. Investigation Workflow

The investigation followed a standard SOC workflow:

1. Capture network traffic.
2. Generate Zeek logs from captured traffic.
3. Identify suspicious communication patterns.
4. Determine the most active source host.
5. Analyze targeted services.
6. Validate evidence using Wireshark.
7. Run custom detection logic.
8. Document findings and recommendations.

---

## 4. Evidence Collection

Network traffic was captured during the attack simulation using tcpdump and processed by Zeek.

Primary evidence sources included:

* conn.log
* ssh.log
* PCAP packet capture
* Wireshark analysis
* Python detection script

These data sources provided both high-level and packet-level visibility into the attack.

---

## 5. Initial Traffic Investigation

The investigation began by reviewing connection activity recorded in Zeek's conn.log.

Analysis revealed repeated connection attempts originating from a single source host. The traffic volume generated by this host was significantly higher than other systems in the environment.

This behavior immediately indicated potentially automated activity requiring further investigation.

### Suspicious Source Host

Source IP:

192.168.111.130

Target IP:

192.168.111.128

The communication pattern showed repeated connections from the same source toward a single destination.

---

## 6. Service Identification

After identifying the suspicious host, destination services were analyzed.

Investigation revealed that the majority of connections targeted:

Port: 22/TCP

Service: SSH

The traffic was highly focused on a single service rather than multiple services, indicating a targeted authentication attack rather than general reconnaissance activity.

This significantly increased the likelihood of brute force behavior.

---

## 7. SSH Activity Analysis

The ssh.log file was reviewed to validate the SSH-related activity.

Observations included:

* Multiple SSH sessions initiated from the same source IP.
* Repeated authentication attempts.
* Consistent SSH protocol negotiation.
* High frequency of connection attempts within a short time period.

The repetitive nature of the sessions suggested the use of an automated password guessing tool.

---

## 8. Packet-Level Validation

The PCAP file was opened in Wireshark for packet-level verification.

The following filter was used:

tcp.port == 22

Analysis confirmed:

* TCP three-way handshakes.
* SSH protocol exchanges.
* Repeated SSH session establishment attempts.
* Continuous communication between the attacker and target systems.

Packet-level evidence directly supported the findings observed within Zeek logs.

---

## 9. Automated Detection

A custom Python detection script was developed to automate identification of suspicious SSH activity.

### Detection Logic

* Parse Zeek conn.log.
* Extract source IP addresses.
* Count SSH connections directed toward port 22.
* Trigger an alert when connection volume exceeds the configured threshold.

### Detection Result

ALERT: Possible SSH Brute Force Detected

Source IP: 192.168.111.130

The script successfully identified the attacking host without requiring manual log review.

---

## 11. Analyst Assessment

Based on log analysis, packet inspection, and automated detection results, the activity was classified as SSH brute force behavior.

The attack demonstrated characteristics commonly observed during password guessing campaigns:

* High volume of repeated SSH connections.
* Single source host.
* Single targeted service.
* Automated connection pattern.
* Consistent authentication attempts.

The combination of these indicators provides strong evidence of brute force activity.

---

## 12. Conclusion

The investigation successfully identified and validated SSH brute force activity originating from 192.168.111.130 and targeting the SSH service running on 192.168.111.128.

Evidence collected from Zeek logs, packet captures, Wireshark analysis, and custom detection logic consistently supported the conclusion.

The attack was detected, investigated, and documented following a SOC-style incident analysis workflow.

---

## 13. Recommendations

* Enforce SSH key-based authentication.
* Disable password authentication where possible.
* Implement account lockout policies.
* Restrict SSH access using firewall rules.
* Monitor authentication failures continuously.
* Deploy automated alerting for abnormal SSH connection volumes.
* Enable centralized log monitoring for rapid incident response.
